# Лабораторная № 3: параллельный TimSort

В `src/main.c` находятся порядок действий программы, замер времени и проверка результата.
В `src/io.c` находятся чтение аргументов и массива, проверка ввода и печать.
В `src/parallel.c` находятся разбиение массива и управление потоками.
В `src/timsort.c` находятся TimSort и слияние отсортированных диапазонов. Требуются C11, POSIX Threads и Python 3 для тестов.

[Отчёт (PDF)](report/Отчет_ЛР3_Барышников.pdf) · [Полная трассировка Ubuntu](report/strace_full.log)

## Сборка и запуск

```sh
make
printf '5\n9 -2 4 0 1\n' | ./build/timsort --threads 2
```

Единственный параметр `--threads N` задаёт положительный лимит потоков,
включая главный. Ввод: длина от 0 до INT_MAX, затем указанное количество
чисел типа int. Пробелы и переводы строк равнозначны. После последнего числа
в интерактивном режиме нажмите Enter. Остаток ввода не читается.
Результат идёт в stdout, время в секундах — в stderr.

```sh
./build/timsort --threads 4 < input.txt > sorted.txt
make test
make sanitize
```

## Устройство

1. `read_token`, `parse_number`, `read_array` проверяют ввод и выделяют массив.
   Токен длиннее 127 символов считается ошибкой ввода. При ошибке память массива
   освобождает `main`.
2. `parallel_timsort` делит массив на min(N, размер) частей.
3. `run_stage` создаёт по одному потоку для каждой задачи, кроме первой:
   первую выполняет главный поток. Затем вызывается pthread_join для всех
   созданных потоков. При ошибке создания уже созданные потоки также ожидаются.
4. `worker` запускает TimSort либо слияние своего диапазона.
5. Части сливаются попарно. Непарная часть переносится на следующий этап.
   Потоки создаются заново на каждом этапе. Последнее слияние выполняется
   главным потоком. Mutex не нужен: задачи имеют непересекающиеся участки
   исходного и вспомогательного массивов, этапы разделены join.
6. `main` проверяет порядок, печатает результат и освобождает массив.

TimSort сохранён: естественные серии, разворот строго убывающих серий,
minrun, двоичные вставки, стек серий с проверкой инвариантов и galloping.
Это адаптивный стабильный алгоритм, а не сортировка фиксированных блоков
вставками с последующим слиянием. Порог galloping фиксирован: 7.

Время CLOCK_MONOTONIC включает память сортировки, создание потоков, сортировку,
слияния, ожидание и освобождение вспомогательных ресурсов. Ввод, проверка
порядка и печать исключены. Память: два массива int плюс O(N) описаний задач
и системные стеки потоков. Худшее время — O(n log n).

Ошибки ввода, выделения памяти, часов, создания/ожидания потоков и вывода
проверяются. При ошибке pthread_join программа завершает весь процесс:
освобождать буферы вручную небезопасно, поскольку поток может ещё работать;
ресурсы процесса освобождает ОС. Это аварийный путь, а не обычная утечка.

## Трассировка потоков

В `report/strace.log` сохранён вывод `strace 6.8` для текущей версии, собранной и запущенной
в контейнере Ubuntu 24.04.5 LTS (Noble Numbat), архитектура `aarch64`.
Повторить запуск можно в Linux при установленном `strace`.

```sh
make trace
```

Входные 13 чисел берутся из `tests/trace_input.txt`, лимит равен четырём потокам.
На первом этапе главный поток создаёт три рабочих потока и сам сортирует одну часть.
На первом уровне слияния он создаёт ещё один рабочий поток. Последнее слияние
выполняет главный поток. Поэтому в логе четыре успешных вызова `clone` за весь запуск.
Строки `futex` показывают ожидание завершения потоков. Если поток уже завершился,
`pthread_join` может обойтись без системного вызова ожидания.

## Проверки

Тесты сравнивают весь результат с Python sorted для случайных, упорядоченных,
обратных массивов, повторов, крайних int и разных лимитов потоков; отдельно
проверяют неверные аргументы, недостающие числа и переполнения ввода.
`make sanitize` повторяет проверки с AddressSanitizer и UndefinedBehaviorSanitizer.
